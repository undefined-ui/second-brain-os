# 研究报告

当一个问题需要的材料超出知识库现有内容时，研究报告就是合适的产物。知识库是起点，而不是全部答案。

<a id="scope-against-what-exists-first"></a>

## 先根据现有内容界定范围

```
I need to understand how companies are deploying agent harnesses in production.
What does my vault already cover, what is thin, and what is missing entirely?
```

得到的回答就是你的研究计划。一份好报告的大部分工作，在于知道哪些内容不必再查；从知识库出发，意味着不用重读去年已经读过的材料。

<a id="fill-the-gaps-deliberately"></a>

## 有针对性地补齐缺口

为知识缺口寻找来源，按流程通过 `raw/` 导入，让它们像其他资料一样生成页面。

抵制捷径很重要。把一篇新文章直接粘进报告草稿，确实能写完报告，却不会改善知识库；下一篇相邻主题的报告，仍然要从原地开始。

<a id="structure"></a>

## 结构

```
Question
What I found          (with page citations)
Where sources disagree
What I could not establish
What would change the conclusion
```

最后两节才让报告值得重读。一份只展示发现的报告，看起来更有说服力，实际上却更没用，因为读者无法判断哪些结论依据坚实，哪些仍很薄弱。

<a id="store-it-as-a-source"></a>

## 把报告作为来源保存

报告放进 `output/`，随后再作为来源导回知识库。

报告是带日期的理解快照。把它作为来源纳入知识库，后来的材料就可以明确反驳它，而不是悄悄取代它。参见[取代关系](../04-structuring/contradictions-and-supersession.md)。
