# 发布与导出

知识库里有些内容值得展示给别人，大部分则不适合。在发布任何内容之前，值得先建立好区分二者的机制。

<a id="deciding-what-is-public"></a>

## 决定哪些内容公开

最简单可靠的办法是明确选择加入：在 frontmatter 中设置 `publish: true`，没有这个字段的内容一律不向外发布。

另一种办法是默认发布、允许选择退出，这是个错误。只要忘记一个标记，就会发布私人内容，而且这种失败悄无声息、无法彻底挽回，因为内容已经被索引了。

<a id="static-site-options"></a>

## 静态网站方案

Obsidian Publish 是官方方案，也是最省事的。Quartz 和 Obsidian Digital Garden 是常见的开源方案，都能从知识库构建静态网站，也都理解双向链接和反向链接。这一点很重要：一个链接损坏的公开 wiki，比普通博客还糟。

无论使用哪种方案，都要检查指向未发布页面的链接会怎样处理。它应该退化为纯文本，而不是跳到 404 页面。

<a id="publishing-a-subset-safely"></a>

## 安全地发布部分内容

有效的模式是：构建步骤只把 `publish: true` 的页面复制到独立文件夹，将指向未发布页面的链接改为纯文本，再用这份副本构建网站。

绝不要让发布工具直接指向正在使用的知识库。一个错误的包含规则就会把所有内容发布出去，而已被爬虫抓取的内容无法真正收回。

<a id="what-publishing-does-to-your-writing"></a>

## 发布会怎样改变你的写作

公开 wiki 会改变你写页面的方式，而且并非全是好事。你开始面向读者写作：更多保留措辞、更多解释，也不再写下尚未成形的想法。

但这些不成熟的想法恰恰是个人知识库存在的理由。如果要发布，可以考虑始终以私人知识库为主，只公开经过刻意挑选的一部分，而不是把整个知识库公开，进而不知不觉地修饰其中所有内容。

<a id="other-exports"></a>

## 其他导出方式

单份报告可以通过 pandoc 直接从 Markdown 导出为 PDF 或 HTML，适合分享一个文档。

不要把整个知识库导出为任何无法重新生成的格式。Markdown 才是核心产物。
