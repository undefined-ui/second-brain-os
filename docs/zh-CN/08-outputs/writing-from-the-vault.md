# 基于知识库写作

写作让知识库从输入材料转变成提高产出的工具。研究已经完成，引用已经齐备，内容已经连接起来。剩下的是组织论证。

<a id="outline-from-concept-pages-not-from-a-prompt"></a>

## 从概念页面拟提纲，而非只凭提示词

```
I want to write about why context length does not replace retrieval. Which of my
concept pages are relevant, what do they collectively argue, and where do my
sources disagree?
```

这样得到的提纲扎根于你读过的内容，也标出了薄弱之处。让模型从零开始列提纲，得到的通常是互联网上的共识观点，而其他人也都在写这些观点。

分歧是最有价值的部分。那里藏着你能说出的、不同于共识的东西。

<a id="cite-your-own-sources"></a>

## 引用自己的来源

草稿中的每个论断，都应能沿着概念页面、来源页面，一直追溯到 URL。这条链让事实核查只需五分钟，而不是花掉整个下午。

它还能防止模型辅助写作特有的一种失败：流畅的句子中包含捏造的具体细节。如果草稿里的一个数字背后没有来源页面，它就不是来自你的研究。

<a id="keep-your-voice"></a>

## 保留自己的表达

从知识库生成草稿，得到的是模型用自己的措辞表达你的材料。作为第一稿可以，作为终稿则不行。

实用的分工是：让智能体整理结构和证据，句子自己写。或者让它起草，再重写每一段。直接发布拼装出来的稿子行不通，因为读者一眼就能看出它是怎么来的。

<a id="close-the-loop"></a>

## 闭合循环

把自己的成品重新导入知识库。

你发布的文章也是来源，和其他资料一样：它们在某个日期清楚地陈述了你的立场。六个月后，知识库能告诉你当时主张什么，以及现在是否仍然相信。

几乎所有人都会跳过这一步，而正是这一步，让同一领域的第二篇文章写起来明显比第一篇快。
