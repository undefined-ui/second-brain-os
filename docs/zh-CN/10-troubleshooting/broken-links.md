# 失效链接与孤立页面

```bash
python3 scripts/link_check.py ~/brain
```

<a id="why-renames-break-links"></a>

## 为什么重命名会破坏链接

在 Obsidian 应用内重命名时，它会更新链接；智能体直接重命名文件则不会。这是智能体维护的知识库中链接失效最常见的原因。

在 `CLAUDE.md` 中加入规则来预防：重命名必须更新所有入站链接，把旧名称加入别名，并记录到 `log.md`。参见[命名与别名](../04-structuring/naming-and-aliases.md)。

<a id="fixing-in-bulk"></a>

## 批量修复

分成两类，分别处理。

**拼写错误与重命名**需要修复：把链接指向正确页面。这类操作可以安全地自动化。

**真正的缺口**指目标从未存在，应加入 `index.md` 的 Gaps 部分。不要为了让链接有效而创建空页面；空页面比记录在案的缺口更糟，因为它会伪装成已有覆盖。

始终在干净的 Git 工作区上执行，这样错误的批量修复可以用一条命令撤销。

<a id="orphans"></a>

## 孤立页面

指没有其他页面链接到的页面。有三种情况。

**本该有链接，却没有。** 找到应该引用它的页面并补上链接。批量导入后，这种情况最常见。

**确实独立。** 很少见，通常意味着这份材料不适合放在 wiki 里。参考资料和检查清单应该放入项目文件夹。

**导入失败。** 一个始终没有建立联系的残缺页面。从 `raw/` 中的原始资料重新导入。

<a id="preventing-both-at-ingest"></a>

## 在导入时同时预防两类问题

能消除大部分后续工作的规则是：同一次运行中完成双向链接，才算导入完成。

以未链接页面结束的导入，就是没有完成的导入。把这条规则落实在技能中，而不是每周清理一次残局。

<a id="after-a-big-import"></a>

## 大规模导入之后

一定要检查。大型补录几乎必然产生孤立页面和近似重复，因为智能体正在快速处理彼此重叠的材料。

把这部分也算进预算：导入一千份来源之后，需要做一轮检查和合并审查。跳过这一步，知识库就会长期混乱。
