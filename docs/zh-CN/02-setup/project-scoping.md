# 项目范围限定

大多数搭建流程都会跳过这一步，随后又困惑：为什么知识库越大，输出质量越差？

当智能体面向整个知识库时，每项任务都要与你曾经保存的一切争夺注意力。它读取覆盖你全部生活背景的根目录 `CLAUDE.md`，再加上它认为相关的其他内容。答案于是越来越宽泛，越来越浅薄。

当它只面向一个项目时，它会读取该项目的 `CLAUDE.md`，看到该项目的文件，然后完成眼前的工作。

<a id="how-to-scope"></a>

## 如何限定范围

在 Obsidian 中，点击左下角的知识库名称，然后依次选择：

**管理知识库 → 打开文件夹作为知识库 → 选择项目文件夹 → 信任**

在终端中，同样的操作就是：

```bash
cd ~/brain/projects/youtube-channel
claude
```

现在，智能体只会读取该项目的指令。

<a id="when-to-use-which"></a>

## 什么时候使用哪种范围

**整个知识库**适用于跨领域工作：规划、复查、询问自己对某个主题知道什么、每周维护、资料导入。广阔视角正是知识层的价值。

**单个项目**适用于产出具体成果：起草、构建、分析本周数据。狭窄的上下文，单一的目标，避免偏离。

粗略规则是：在整个知识库中规划，在单个项目中交付。

<a id="passing-knowledge-into-a-project"></a>

## 将知识传入项目

缩小范围会切断智能体与 wiki 的直接联系。通常这正是你想要的，但偶尔不是。可以用两种方式搭桥：

- 在项目的 `CLAUDE.md` 中链接相关概念页面，并把少量真正重要的页面复制到项目的 `Inputs/` 中。
- 或者先在整个知识库中提出研究问题，将答案存入项目的 `Inputs/`，再缩小范围开展工作。

第二种方式更好。它让你继续掌握什么重要的判断权，而这正是你不该委托出去的部分。
