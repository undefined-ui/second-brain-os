# Git、同步与备份

知识库是一组文本文件，几乎是理想的 Git 仓库；也正是 Git，让智能体能够安全地无人值守运行。

没有版本控制，出问题的运行就是一团谜。有了版本控制，智能体的每一处改动都可以在 diff 中阅读，并用一条命令撤销。

```bash
cd ~/brain
git init
git add .
git commit -m "initial vault"
```

<a id="what-to-ignore"></a>

## 应该忽略哪些文件

```
.obsidian/workspace*
.obsidian/cache
.DS_Store
.trash/
```

提交 `.obsidian/` 的其余内容，让插件列表和设置随知识库一起保存。绝不要提交 API 密钥；Local REST API 的密钥保存在插件数据中，因此第一次推送前，要检查 `.obsidian/plugins/` 里有什么。

如果知识库有任何私密部分，远程仓库也要设为私有。第二大脑可能是最能反映一个人真实情况的文档之一。

<a id="commit-around-agent-runs"></a>

## 在智能体运行前后提交

大批量导入之前和之后都提交一次。这样，坏批次只需执行 `git checkout .`，而不是花一下午手动修复。定时任务应自行提交工作，并在提交信息中标明是哪次运行，确保几个月后仍能读懂历史。

<a id="sync-across-machines"></a>

## 在多台设备间同步

- **Git 远程仓库：** 免费，有版本记录，到处可用，需要养成拉取和推送的习惯。
- **Obsidian Sync：** 付费，端到端加密，对移动端支持完善。
- **通用云盘：** 可以使用，但有一点需要注意。如果同步客户端和智能体同时改写文件，就会产生冲突副本。采用这种方式时，请把长时间运行的智能体任务固定在一台机器上。

<a id="backups"></a>

## 备份

同步不是备份。同步会把一次错误删除传播到所有设备。

保留一份不在同步链路中的副本：定期归档到外部存储，或另一个独立的远程仓库。真正需要恢复之前，先测试一次恢复流程。你要防范的不是硬盘损坏，而是三周前某次自动化悄悄重写了两百个页面。
