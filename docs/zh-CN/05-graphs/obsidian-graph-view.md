# 读懂 Obsidian 图谱视图

全局图谱就是大家常晒的截图。它也是应用里最不实用的视图。

达到两百个页面时，它就像一团乱麻；这团乱麻除了告诉你“这里有很多页面”之外，什么也说明不了。它擅长的是让你一眼看出形态：孤立的团块、一个占据主导的枢纽，或边缘散落的无连接节点。

<a id="local-graph"></a>

## 局部图谱

这个视图才真正有用。打开一个页面，显示局部图谱，将深度设为二。

你要观察两件事。一跳之内的内容应该明显相关；其中任何出人意料的内容，要么是应该删除的装饰性链接，要么是值得进一步阅读的联系。两跳范围内缺少什么，则会告诉你这个页面在哪些方面连接不足。

查看刚写完页面的局部图谱，是最快的质量检查，只需五秒。

<a id="filters-that-make-the-global-view-usable"></a>

## 让全局视图变得可用的筛选设置

- **按类型筛选。** `-path:sources` 会隐藏来源页面，只留下概念图谱，而有意义的内容就在这一部分。来源的数量远多于概念，在视觉上会将概念淹没。
- **用颜色分组。** 为概念、实体和综合页面设置不同颜色。一个没有概念页面的簇，只是一堆尚未处理的来源。
- **孤立节点开关。** 有意识地开启孤立节点显示，看看出现了什么，然后修复或删除它们。
- **深度和作用力。** 降低链接吸引力，可以让不同簇拉开足够距离，显露出桥梁。

<a id="what-to-look-for"></a>

## 应该留意什么

**边缘只连接到一个对象的节点。** 通常是失败的导入。来源页面写好了，概念却没有反向链接回来。

**中间一个巨大的节点。** 某个枢纽吞没了整个图谱。把它拆开。

**两个簇只通过一个页面连接。** 这个页面在发挥真正的作用。它也很脆弱：如果它有错，两个簇对彼此的理解都会出错。

**一个你不熟悉的簇。** 通常是屏幕上最有趣的东西。这说明知识库已经积累了某个主题的材料，而你此前并没有有意识地跟踪这个主题。

<a id="what-the-view-cannot-tell-you"></a>

## 视图无法告诉你什么

它能显示页面之间存在连接，却从不说明为什么连接。无论一条边表示“支持”“反驳”，还是“顺带提过一次”，看起来都一样。

这种局限，就是下一页所讨论方法的全部理由。
