# 值得跟踪的图谱指标

四个数字，每月检查一次。它们随时间的变化趋势，能告诉你系统是否在正常发挥作用，而日常使用时未必看得出来。

```bash
python3 scripts/vault_stats.py ~/brain
```

<a id="orphan-rate"></a>

## 孤立页面比例

没有入链的页面占全部页面的比例。

这是知识库中最具诊断价值的单个数字。孤立页面比例上升，意味着资料导入只是在编写页面，却没有建立连接，而这正是让 wiki 退化回文件夹的失败方式。

低于百分之五是健康的。高于百分之十五，说明有问题的是导入指令，而不是你的使用习惯。

<a id="average-degree"></a>

## 平均度

每个页面的链接数。

低于二时，图谱几乎没有有效连接，检索不会比搜索更好。对于个人知识库，三到八是实用范围。明显高于十时，要检查是否添加了装饰性链接；它们会抬高数字，却降低图谱的实用价值。

把这个指标与页面数量一起观察。知识库扩大一倍，度保持不变，是正常情况；度下降则说明新页面建立的连接少于已有页面。

<a id="component-count"></a>

## 连通分量数量

有多少个彼此断开的孤岛。

理想情况是一个大的连通分量包含大多数页面，再加上少数真正独立的主题。如果主要连通分量包含的页面不足大约百分之八十，知识库就已经碎片化，回答会系统性地不完整，而表面上看不出任何问题。

<a id="stale-page-rate"></a>

## 陈旧页面比例

`updated` 日期距今超过九十天的概念页面，占所有概念页面的比例。

有些内容长期不变是合理的：关于一个已有定论的想法，写得好的页面不需要再改。但如果来源不断进入，而大多数概念页面几个月都没有更新，就意味着新材料落在了新页面上，而没有更新现有页面。最后就会出现四个页面讲同一件事的情况。

```dataview
TABLE updated FROM "wiki/concepts"
WHERE updated < date(today) - dur(90 days)
SORT updated ASC
```

<a id="what-not-to-track"></a>

## 不必跟踪什么

页面数量和字数。不管知识库是否变好，这两项都会增长，因此它们令人满足，却没有用。页面翻倍、孤立页面比例也翻倍的知识库，其实变差了。

<a id="recording-them"></a>

## 如何记录

每月把四个数字追加到一篇笔记中。趋势才是有用信息；单次读数几乎说明不了什么，而你也不会记得上个季度的孤立页面比例。
