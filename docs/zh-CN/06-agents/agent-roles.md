# 智能体角色

让一个智能体包办所有事情，会让每项工作都表现平庸。优秀的导入智能体与优秀的复查智能体需要不同指令，把它们塞进同一个提示词，只会互相削弱。

六个角色可以覆盖整个知识库，其中四个只有读取权限。角色定义位于 [`agents/`](../../../agents/README.md)。

<a id="ingestor"></a>

## 导入者

读取 `raw/`，编写 wiki 页面，建立链接，更新索引和日志。它比其他任何角色写入的内容都多，其输出质量决定着所有后续环节。

它的指令刻意保持狭窄：不回答问题，除添加链接外不重构现有页面，也不删除内容。如果导入者在导入的同时重新组织知识库，就会产生难以审查的运行结果，因为内容变化与结构变化混在同一份差异中。

<a id="linker"></a>

## 链接者

找出现有页面之间在导入时遗漏的联系。

在导入之后及每周运行。只添加链接，不创建内容，也不重写内容。将它与导入者分开很重要，因为良好的链接需要广泛阅读整个知识库，这与仔细阅读单个来源是不同的工作。

它只有一条规则：将两个页面并排读完后，你应该认同它添加的链接。以链接数量为优化目标的链接者，看起来很高效，却会破坏图谱。

<a id="reviewer"></a>

## 复查者

只读。生成定期回顾：发生了什么变化、注意力投向了哪里、哪些内容相互矛盾，以及下一步该读什么。

只读并不是出于谨慎，而是保证回顾可信的必要条件。能够编辑的复查者会边看边修小问题，最终报告描述的就是一个已经不存在的知识库。

<a id="researcher"></a>

## 研究者

只读。根据知识库回答问题，引用页面，并指出缺少哪些内容。

它也是你最常交流的角色，因此最需要遵守“不回退到通用知识”的规则。参见[查询技能](../../../skills/README.md)。

<a id="graph-analyst"></a>

## 图谱分析者

只读。运行指标计算，找出枢纽、桥梁和簇，并解释这些数字对检索意味着什么。每月运行。

它与质量检查者分开，因为分析和修复需要相反的倾向：前者应该注意到所有问题，后者应该尽量少改动。

<a id="curator"></a>

## 整理者

只读。每季度提出哪些内容应精简、归档或合并的建议。

只提建议，从不执行操作。删除是一种无法仅靠查看差异就恢复的操作，因此必须由所有者来决定。

<a id="roles-not-worth-creating"></a>

## 不值得创建的角色

**删除者。** 删除应由你决定，并在执行时留下记录。整理者提出建议，你来裁决。

**摘要者。** 对已经是摘要的页面再做摘要，会形成一层更偏离事实的内容，而且人们会阅读这一层，取代阅读它下面的内容。

**标签者。** 打标签是在导入时基于完整上下文做出的五秒判断。单独再跑一遍，可用上下文反而更少，标签质量也更差。

<a id="handoffs"></a>

## 工作交接

角色通过知识库沟通，而不是彼此直接对话。导入者把缺口写进 `index.md`，链接者读取它们。导入者记录运行日志，复查者读取日志。

这是有意设计的。以文件作为接口，意味着每次运行都可以事后检查，也可以替换某个角色，而不影响其他角色。
