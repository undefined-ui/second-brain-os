# 安全护栏

本节建立在一条规则之上：

**用权限，而不是提示词来设定边界。**

告诉智能体不要做某件事，只是一项偏好，而不是边界。如果智能体在技术上能够删除文件、清空文件夹或发送邮件，那么总有一天，它会在你未曾预料的上下文中这样做。

在权限层面控制哪些操作能够发生。这样，`CLAUDE.md` 中的指令就是边界之上的偏好，而不是保护笔记免受一次糟糕运行影响的唯一屏障。

<a id="scope-write-access"></a>

## 限定写入权限

智能体需要写入知识库，但不需要写入你的主目录。一个拥有宽泛文件系统权限的定时任务，是用大范围的潜在破坏换取一点便利。

连接器也遵循同样原则：只要提供只读选项，就使用只读。一个只能读取的日历连接器，无论如何误解指令，都无法取消会议。

<a id="never-delete-without-a-record"></a>

## 删除必须留下记录

删除是一种无法仅靠查看差异就恢复的操作，因为内容已经消失，只剩下它不再存在的事实。

规则是：任何页面删除前，都必须在 `log.md` 中留下一行，写明名称和删除原因。合并也算删除。始终遵守这条规则，消失的页面就总能追溯，“那个页面去哪儿了”也不再是无法回答的问题。

<a id="git-is-the-real-safety-net"></a>

## Git 才是真正的安全网

上面的所有护栏都是预防措施。当某一道护栏失效时，Git 才能救你。

任何大规模写入操作开始前，先提交一次。定时运行也应提交自己的工作。这样，糟糕的导入可以用 `git checkout .` 撤销，糟糕的合并只需一次 revert。

偶尔读一读定时运行产生的差异，尤其是在最初几周。这能让你了解智能体早上七点实际上做了什么，而它的实际行为往往与你的假设不同。

<a id="dry-runs"></a>

## 试运行

凡是会涉及许多文件的操作，都先以仅报告模式运行一次。

```
Do a dry run: list every page you would create, update or delete, and the links
you would add. Write nothing.
```

花一分钟阅读输出，就能在错误理解变成四百处修改之前发现它。

<a id="watch-for-scope-creep"></a>

## 留意范围扩张

智能体会扩大任务。让它导入资料，它可能顺手整理无关页面、修正格式，或为了保持一致而重命名某些内容。每一项都说得通，但加在一起就意味着，不通读所有变化，你根本不知道一次运行做了什么。

明确指示：只做要求的工作，列出注意到的其他问题，不修改任何其他内容。

<a id="what-not-to-put-in-the-vault"></a>

## 哪些内容不该放入知识库

凭据、API 密钥、任何你有义务保密的内容，以及他人的私人信息。

原因并不是智能体一定会泄露它们，而是知识库是一棵会被同步、提交、备份，偶尔还会分享的文件树。每多一份副本，这些内容就多一个存放位置。参见[隐私](../09-maintenance/privacy-and-secrets.md)。
