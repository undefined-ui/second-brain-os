# 钩子

钩子由事件触发，而不是按时间计划触发。对于每次都必须执行的事情，钩子是合适的工具，而这些恰恰也是提示词指令迟早会遗漏的事情。

<a id="worth-hooking"></a>

## 值得设置钩子的事项

**写入前验证。** 检查 frontmatter 能否解析，以及必需字段是否齐全。写入时发现格式错误，问题就不会发生；一个月后才发现，则意味着这个页面一个月来一直没有出现在任何查询中。

**运行后检查。** 失效链接应在刚产生时就被发现，此时有足够上下文，可以正确修复。

**定时运行后提交。** 避免出现一次运行修改了四十个文件，却没有留下提交的情况。

**删除时通知。** 无论何时，任何删除都必须显现出来。删除操作足够少，通知几乎没有负担，而一旦触发就很重要。

<a id="not-worth-hooking"></a>

## 不值得设置钩子的事项

任何缓慢的操作。如果钩子在每次文件写入时都运行，而且耗时两秒，就会把四十页的导入变成九十秒的停顿，最终你会将它禁用。

任何需要判断的操作。钩子应做机械性检查。一个试图判断页面质量是否足够好的钩子，既会误判合格内容，也会放过不合格内容。

<a id="keep-them-fast-and-quiet"></a>

## 保持快速、安静

钩子应该在远少于一秒的时间内完成，通过时不输出任何内容。成功也写日志的钩子，会让你养成忽略钩子输出的习惯；等哪天真正失败时，就等同于没有钩子。

<a id="failure-behaviour"></a>

## 失败时的行为

明确决定钩子失败是否阻止当前操作。

验证钩子应该阻止：未通过字段规范验证的页面不应写入。通知钩子不应该阻止：通知失败，不是丢弃工作成果的理由。

最糟糕的情况是，某个阻塞式钩子因无关原因失败，悄悄让定时导入停了一周。凡是会阻止操作的检查，都必须简单到只会因它本来要检查的问题而失败。
