# 链接规则

链接承载了整个结构的价值。没有链接，你得到的只是一个存着命名规范文件的文件夹，也就是一种搜索索引，而搜索索引早已存在。

<a id="the-rule"></a>

## 规则

在每个页面中，任何概念或实体第一次出现时都要加上链接。

仅此而已。只要始终遵守，图谱就会自然形成，无需单独补链，也无需专门的维护仪式。

<a id="link-do-not-restate"></a>

## 建立链接，不要重复解释

如果正在解释的内容已经有了页面，链接过去，然后继续。

这能让知识集中在一个地方。如果一个概念的解释以四种略有不同的版本分散在四个页面中，更新时就必须把四处都找出来，而你不会做到。通过链接，它只需存一份，也只需改一处。

<a id="both-directions"></a>

## 双向链接

新页面链接到它引用的内容，被引用的内容也链接回来。

单向链接会产生一些引用了知识库、却永远无法从知识库中找到的页面。它们存在，内容也正确，但没有任何路径能发现它们。Obsidian 会显示未链接的反向提及，帮助你发现这些问题，但智能体应该在导入时就闭合这个循环，而不是留给你处理。

<a id="links-that-do-not-exist-yet"></a>

## 指向尚不存在页面的链接

仍然写出链接，然后要么在同一次运行中创建目标页面，要么把它记录在 `index.md` 的内容缺口部分。

缺口本身就是有用的信息。一个已经被三个来源链接、却尚不存在的页面，恰好就是下一步应该编写的内容，或应该继续阅读了解的主题。

不可接受的是永久性缺口。指向永远不会存在页面的链接，会让图谱对自己的覆盖范围作出虚假表示。

<a id="how-many"></a>

## 链接数量

没有固定目标数量，但结构形态很重要。没有出链的页面是死胡同。有四十条出链的页面，通常是一个伪装成页面的列表。

关注整个知识库的平均值，而不是某一个页面。平均每页不足大约两条链接时，图谱连接得还不够充分，无法回答单个页面无法回答的问题。用 `scripts/vault_stats.py` 跟踪这个指标。

<a id="hub-pages"></a>

## 枢纽页面

有些页面会不断积累链接，直到所有路径都经过它们。一个每份来源都会涉及的宽泛概念会成为枢纽；一旦如此，周围图谱就不再提供有意义的信息，因为任意两处之间都只隔两步。

解决办法是把枢纽拆成大家实际要链接的具体想法。如果四十个页面都链接到同一个宽泛概念，它们实际上是在链接这个概念的四个不同方面。

<a id="decorative-links"></a>

## 装饰性链接

每一条链接都在声明：两个页面之间存在值得追踪的关系。仅仅因为某个词碰巧出现就添加的链接，是噪声。这类链接多到一定程度，会让图谱和空图谱一样无法使用。

判断方法是：研究这个主题时，你会沿着这条链接继续阅读吗？如果不会，就删除它。
