# 去重与合并

重复不可避免。两个来源用不同的词描述同一个想法，某个别名没有补上，或者在知识库尚未建立相关概念前就进行了批量导入。问题不在于如何彻底杜绝重复，而在于如何在两个页面都积累起链接之前发现它们。

<a id="finding-them"></a>

## 如何发现重复

按可靠程度排序，可以观察这些信号：

- **标题相似。** 检查成本低，能发现单复数和缩写造成的重复。
- **别名重叠。** 两个页面使用同一个别名，始终是一个问题。
- **入链来源相同。** 如果同样的五个来源都同时链接到两个页面，它们通常应该是同一个页面。
- **内容相似。** 成本高，但能发现名称看起来毫无关联的重复内容。

`second-brain-lint` 会执行前三项检查并提出合并建议。它不会实际执行合并，这是有意为之。

<a id="why-merging-is-not-automatic"></a>

## 为什么不自动合并

合并在一个关键层面上是不可逆的：两个页面合为一个后，你就无法判断哪个主张原本来自哪个页面，而智能体对“它们是同一个东西”的判断，恰恰最容易出错。

两个从摘要看起来完全相同的想法，往往一个是一般情形，一个是特殊情形，合并会永久抹去这种区别。

所以，智能体提议，你来决定。审查一次合并只需要十五秒。

<a id="the-procedure"></a>

## 操作流程

当你批准一次合并后：

1. **按规范名称选择保留的页面**，而不是按哪个页面更长来选。
2. **合并内容**，保留每个不同的主张及其来源。重叠的主张合为一项，有差异的主张则全部保留。
3. **合并别名**，将被移除页面的标题也加入保留页面的别名。
4. **重定向入链**，让它们指向保留的页面。
5. **仅当旧路径存在知识库之外的引用时，才保留一个占位页。** 否则删除它。
6. **在 `log.md` 中记录合并**，写明两个名称，让消失的页面有迹可循。

第 6 步最容易被智能体跳过，却也是你日后最需要的一步。一个毫无记录就消失的页面，与被误删的页面没有区别。

<a id="do-not-dedupe-live"></a>

## 不要在导入过程中去重

在资料导入期间执行合并，意味着智能体一边添加内容，一边重构知识库；一次错误合并就会混在原本正常的工作之中。

每周或大规模导入之后，在干净的 git 状态下单独执行一次去重。这样，错误合并只需一次 `git checkout` 就能撤销。
