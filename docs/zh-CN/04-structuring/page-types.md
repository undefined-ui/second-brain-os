# 四种页面类型

四种类型，各有职责。每个页面都在 frontmatter 中声明类型，让你能按结构查询知识库，而无需把所有内容读一遍。

<a id="sources"></a>

## 来源

每个导入条目对应一个页面，记录这篇文章、这个视频、这篇论文或这段对话说了什么。

把主张当作主张来记录：这个来源声称 X，同时附上 URL、作者和日期。它不作评价，也不混入其他来源的看法。

来源页面构成审计轨迹。当概念页面提出令人意外的说法时，你可以通过背后的来源页面核查：它是否真的曾经成立。

<a id="entities"></a>

## 实体

人物、组织、产品、工具。记录它是什么、为什么会出现在你的知识库中，以及哪些内容提到了它。

实体页面创建成本很低，但它的价值往往要等知识库变大后才显现。它们会成为自然的汇合点：三个原本无关的来源都提到了同一家公司，便突然通过这家公司连接起来，而这种联系往往正是值得注意的东西。

不要写人物传记。实体页面应存放与你的知识库相关的内容，而不是维基百科的内容。

<a id="concepts"></a>

## 概念

想法、方法、框架、论点。这些页面会不断积累价值。

概念页面用平实的语言解释想法，说明它来自哪里、有什么支持证据、有什么反对意见，以及哪些地方仍不清楚。写得好的页面，即使读者没有看过任何来源也能理解，包括一年后的你自己。

这是唯一一种智能体应该跨来源综合内容，而不仅仅是记录内容的页面类型。

<a id="synthesis"></a>

## 综合

比较、主题、开放问题。只有在说出了任何单个来源都没有说过的内容时，综合页面才有存在的意义：两个来源存在分歧，三个来源描述了同一种模式，或者某个问题在互不相关的材料中反复出现。

保持这类页面可靠的规则是：不要为了拥有综合页面而编写综合页面。被要求做综合的智能体总会产出些什么，而硬凑出来的主题，是让 wiki 迅速充满言之凿凿的胡话的捷径。

<a id="where-the-types-blur"></a>

## 类型边界模糊时

有些内容确实可以属于两种类型。以作者名字命名的方法，既是实体也是概念。选择一种，通常选概念，再用别名把另一种称呼指向它。

有些内容不属于任何一种。食谱、配置片段、检查清单等属于参考材料，而不是知识，应该放在项目文件夹中，而不是 wiki 中。
