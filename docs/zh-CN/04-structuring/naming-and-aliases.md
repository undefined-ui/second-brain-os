# 命名与别名

Wikilink 按名称解析，所以名字并非装饰，而是整个图谱建立其上的键。

<a id="canonical-titles"></a>

## 规范标题

一个页面对应一个规范标题，使用你与该领域的人交谈时会采用的名称。

下面这些实用规则可以避免大多数麻烦：

- **使用单数，而不是复数。** 使用 `Vector database`，不要用 `Vector databases`。
- **标题写出缩写的全称，将缩写放入别名。** 标题面向读者，别名服务于链接。
- **标题中不放日期和版本**，除非这个事物本身确实就是某个版本。名为 `MCP spec 2026-07` 的页面一个月后就会过时；名为 `MCP`、内部维护版本历史的页面则不会。
- **不要添加只适用于你自己知识库的前缀。** `Concept - RAG` 会妨碍链接语法，却没有任何收益。

<a id="aliases"></a>

## 别名

把同一个主题的所有名称列在 frontmatter 中：

```yaml
title: Retrieval augmented generation
aliases: [RAG, retrieval-augmented generation]
```

别名可以防止知识库悄悄为同一事物长出三个页面。没有别名时，使用 RAG 的来源会创建 `RAG`，写出全称的来源会创建另一个页面，而两个页面互不知情。

创建页面时就添加别名，不要以后再补。等你发现重复时，两个页面都已经有入链了。

<a id="two-things-with-the-same-name"></a>

## 同名的两个事物

在标题中消除歧义，而不是添加没人会输入的后缀：

```
Mercury (planet)
Mercury (element)
```

然后，将不带限定的名称作为知识库中主要含义的别名；如果两种含义都重要，就不要为任何一个设置这个别名，迫使智能体明确选择，而不是猜测。

同样的规则也适用于同名的人，以及名称与知名产品冲突的个人项目。

<a id="renaming"></a>

## 重命名

在 Obsidian 应用内重命名时，它会更新链接。智能体直接重命名文件则不会，而这正是智能体维护的知识库中最常见的失效链接来源。

写进 `CLAUDE.md` 的规则是：重命名必须遵循明确记录的流程。更新文件、更新所有入链、将旧名称添加为别名，并记录到 `log.md`。别名很重要，因为它能让外部引用和你自己的记忆继续有效。

然后运行 `scripts/link_check.py`，确认没有悬空链接。
