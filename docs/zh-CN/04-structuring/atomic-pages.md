# 一个页面，一个想法

一个页面只承载一个想法，并把它解释得足够清楚，让从未看过原始来源的人也能理解。

这条规则源于检索的工作方式。智能体回答问题时，会把整个页面放入上下文。一个涵盖四个主题的页面，每次被用到都会把另外三个不相关主题一起带入上下文。只涵盖一个主题的页面则能被准确链接、准确检索，也能在更新时不影响其他内容。

<a id="what-atomic-means-here"></a>

## 这里的“原子化”是什么意思

它不等于简短。一个概念页面可以有数百词。原子化意味着页面只有一个主题，而且无需使用“和”字，就能为它起一个准确的标题。

如果标题需要“和”，或者页面中有讲述互不相关主题的小节，那么它就应该拆成两个页面。

<a id="splitting-a-source"></a>

## 拆解一个来源

一篇文章通常能提炼出一到三个值得独立成页的概念，再加上一个记录文章本身内容的来源页面。

判断某个内容是否值得独立成页，可以问：不回头引用这份特定来源，能否把它解释清楚？如果一个想法只有作为“这篇文章提出的观点”才有意义，它就应该留在来源页面中。如果一个想法会在其他来源中反复出现，就需要单独成页，因为其他来源将汇集到这里。

<a id="the-failure-in-both-directions"></a>

## 两个方向的失败

**拆分过度**会从一篇文章生成十个页面，每个页面只是复述一个段落，而且都只链接回原始来源。图谱看起来密集，却没有传达任何信息。智能体更容易犯这种错误，因为拆分给人的感觉像是在认真全面地处理资料。

**拆分不足**则会让来源页面变成文章摘要，而整个 wiki 中没有任何概念。最后得到的只是一个可搜索的资料归档，而你本来就已经有了。

拿不准时，少建几个页面。以后再合并成本不高；理清一百个碎片则不是。

<a id="length"></a>

## 长度

概念页面如果不足大约八十词，通常是一个不合格的占位页，而不是高效精炼的页面。要么来源并没有真正涉及这个概念，要么智能体半途而废。这两种情况都值得在质量检查时发现。

页面如果超过大约一千词，通常是两个想法交织到了一起。读一遍，找出它们之间的分界。
