# LLM wiki 模式

本指南实现的具体模式，由 Andrej Karpathy 于 2026-04-04 以 gist 的形式发布。

用一句话概括这种反转：过去是你维护笔记，偶尔就笔记向 AI 提问；现在由 AI 维护 wiki，你来阅读它。

<a id="what-the-pattern-specifies"></a>

## 这种模式规定了什么

**Wiki 是核心。** 原始资料是你保留、却很少打开的档案。你和智能体都以 wiki 为工作基础：使用自然语言书写，每页一个想法，页面之间密集关联。

**整合编纂，而非摘要堆积。** 每份新资料都融入现有页面，而不是作为另一份摘要堆在旁边。随着资料积累，概念页面不断完善，而不会变成逐条罗列各个来源说法的清单。

**三种操作。** 资料导入负责引入新内容，结构检查负责保持结构健全，查询负责依据 wiki 回答问题。其他操作都是这三者的变体。

<a id="why-it-holds-up"></a>

## 为什么它能持续运作

因为它消除了让以往所有系统失效的那项任务。每读一篇论文，就要为五十条笔记彼此建立联系，这项工作确实枯燥，人们终究会停止；维护者一旦疲倦，wiki 就会衰败。

另一个原因是它不需要基础设施。只需 Markdown 文件、双向链接，以及能读写文件的智能体。没有数据库，没有必须持续更新的索引，也没有必须依赖的服务。

<a id="where-the-gist-stops"></a>

## 那篇 gist 止步于哪里

它描述的是意图，而非实现：整合新资料，定期进行结构检查，并将 wiki 作为核心。

具体机制留给了实现者，所以每个实现都不同。整合时如何处理矛盾，页面必须包含什么，何时运行检查，wiki 面向谁书写。本指南在[组织结构](../04-structuring/README.md)中给出了答案，但这些是具体取舍，并不是模式本身。

<a id="what-people-build-on-top"></a>

## 人们在此基础上添加了什么

常见扩展包括日志层、项目层和定时自动化。本指南在[两个层次](two-layers.md)与[智能体](../06-agents/README.md)中介绍后两者。

这种模式传播迅速，也因为它的基本组件很普通：任何拥有智能体和一个文件夹的人都能运行它，所有实现也都是可读的 Markdown。[资源](../../../resources/skills.md)中列出了值得阅读的实现。
