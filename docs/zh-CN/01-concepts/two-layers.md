# 两个层次

大多数第二大脑系统失败，是因为它们选择了一种结构，却试图让它完成两种工作。

**知识层**回答“我对 X 知道些什么”。它按想法组织，会持续增长，价值在于页面之间的链接。这就是 LLM wiki 模式：输入来源，产出概念，让一切互相关联。

**项目层**回答“我这周在做什么”。它按从输入到输出的流水线组织，大部分内容在项目交付时就会失去活跃度。

把两者混在一起，会产生不同的问题。混入项目文件夹的 wiki 会塞满过期任务清单，让每次搜索的质量下降；混入概念笔记的项目系统，则会把工作文件埋在工作时根本没人打开的资料下面。

<a id="how-they-connect"></a>

## 两者如何连接

项目消费知识层的内容，也将成果反馈给它：

```
        wiki/concepts ──────> project Inputs/
              ▲                      │
              │                      ▼
        ingest what                Process/ ──> Outputs/
        you learned                              │
              └──────────────────────────────────┘
```

工作会产出值得保留的资料。几乎每个人都会跳过导入自己已完成作品这一步，而恰恰是这一步，让同一领域的第二个项目显著快于第一个。

<a id="which-to-build-first"></a>

## 先建立哪一层

如果你读得很多、记住的很少，先建立知识层。

如果你的问题是每天早上都要向聊天窗口重新解释自己的情况，先建立项目层。

最终两层都需要。请参阅[知识库结构](../02-setup/vault-structure.md)，了解如何在同一个文件夹里让它们保持分离。
