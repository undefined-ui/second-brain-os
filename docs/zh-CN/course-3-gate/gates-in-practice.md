# 决策关卡的实际运用

判断一个决策关卡好不好，只需看两个数字：它答对的频率，以及它识别自己可能出错的能力。本篇先讨论这两点，再如实介绍用于这项工作的最新工具目前表现如何。

<a id="thresholds-and-failing-closed"></a>

## 阈值与默认拒绝放行

决策关卡的每个答案都带有置信分数。分流规则是：只有预测标签具有确定性的处理程序，*并且*置信度超过阈值，才走廉价路径。其他情况全部交给主模型。这就是默认拒绝放行——关卡可以不知道，但不允许猜测。陌生条目应当始终交给有判断能力的模型，绝不能因为某个处理程序得到 51% 的置信度，就把条目交给它。

阈值本身是一项业务决策，而非建模决策。应比较快捷路径执行错误操作的代价，与一次不必要的升级处理的代价。新闻简报放错文件夹，代价很低，因此这条路径可以使用较低阈值；自动归档一封录用通知，代价就很高，因此这条路径要么设置较高阈值，要么干脆不开启。整个模式的可运行代码见[基于置信度设置关卡的路由器](../track-jev/build-router.md)。

<a id="calibration-on-your-own-labels"></a>

## 用自己的标注数据校准

置信度为 0.9，并不意味着十次能答对九次，除非有人专门把它校准成了这个含义。在验证之前，无论哪个供应商给出的置信分数，都应只视为排序依据。验证过程很简单：留出关卡从未见过的已标注样本，把预测结果按置信度区间分组，再测量各区间的准确率。把阈值设在区间准确率满足你容忍度的位置。

一个独立垃圾信息基准测试（pniessen 的 jev-test，使用公开 SMS 和 Enron 语料）展示了健康的决策关卡是什么样：最低和最高置信度区间的预测准确率均为 100%，涵盖了 83% 的流量，几乎所有错误都集中在一个很窄的中间区间。将中间区间升级处理后，剩下的 82.7% 消息没有一个错误。这正是决策关卡按设计发挥作用的样子——大部分输入流以低成本处理，所有疑点都交给上层。

<a id="jev-honestly"></a>

## 如实看待 Jev

供应商声称，Jev 的端到端耗时为 70–500 毫秒，而 LLM 工作流需要数秒；每百万输入 token 的价格为 0.042 美元，输出免费。发布两周后，首批独立测试数据已经出现：

- **电子邮件分类。** 在早期第三方测试的约 18,500 封邮件中，TF-IDF 逻辑回归得到 98.4% 的准确率，Jev 为 98.3%——它与一种 2003 年的方法在统计上打成平手，而后者在笔记本电脑上几秒钟就能训练好。
- **钓鱼邮件检测。** 在 anisselbd 的 jev-phishing-bench（2,000 封邮件）上，向 Jev 提一个复合问题——这是不是钓鱼邮件——得到 62.6% 的准确率，而 Claude Haiku 4.5 为 81.3%。将问题拆成五个范围明确的信号问题，再用 1,000 个标注样本拟合的逻辑回归组合答案后，Jev 达到约 95%，Haiku 为 93.2%，但差异没有统计显著性。准确率来自问题设计的工程工作，并不会默认送到你手里。
- **“零幻觉”** 按 TypeSafe 自己的脚注，仅表示符合数据模式。每个答案都是合法选项；选中错误的合法选项，恰恰就是上述准确率数字所衡量的错误。
- **开箱即用的置信分数是排序依据，并非经过校准的概率**——独立测量发现，在多项任务上，校准误差大到不足以信任默认阈值。请用自己的标注数据设置阈值；据报告，只需约五十个标注样本拟合一次温度校正，就能有所帮助。

<a id="when-logistic-regression-simply-wins"></a>

## 逻辑回归直接胜出的情况

如果关卡的问题固定、领域是你自己的，而且你能标注几百个样本，逻辑回归就具有每次调用免费、本地运行、保护数据隐私、结果确定等优势，而且根据目前的证据，它不输给上述任何一种方案。Jev 真正适合的是冷启动：还没有标注数据、需要一次对每个条目问许多问题、选项集合很大，或者数据分布漂移得比重新训练还快。但这些优势必须在你的数据上得到证明，而不是供应商的数据。任何方案在击败三十分钟就能建立的基线之前，都不能进入处理流水线。下一篇就来建立这个基线：[决策关卡实践](gate-practice.md)。

最后明确一下命名：决策关卡是一层架构；Jev 是实现它的一种方式。[Jev 工程手册](../track-jev/system-one-models.md)深入介绍这种实现方式，而本模块始终围绕这一架构层展开。
