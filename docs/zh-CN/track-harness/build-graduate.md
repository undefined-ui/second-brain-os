# 实践：何时升级

现在，你拥有大约 150 行代码，实现了所有运行框架都会做的事：循环、执行、权限关卡、预算控制、停止。动手构建的过程就是学习。这一页是结业访谈：这些代码还缺什么，哪些现成方案能填补各项缺口，以及如何坦诚地做出选择。

下面用 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 作比较，因为它把 Claude Code 自身的运行机制封装成库，也是本次实践最自然的升级路径；[生态概览](harness-landscape.md)介绍了其他选择。

<a id="gap-one-compaction-quality"></a>

## 缺口一：压缩质量

你的预算控制会删除旧轮次，只留下一行摘要。这样会丢掉决策、文件路径和做了一半的事项——恰恰是最值得保留的内容。Agent SDK 继承了 Claude Code 的自动上下文管理：恰当地概括对话记录，在丢弃庞大工具输出的同时保留意图，并通过钩子控制哪些内容留下。粗略梗概与优质摘要之间的差距，就是智能体能继续工作还是只能重做一遍的差距——[上下文工程](context-engineering.md)解释了原因。

<a id="gap-two-parallel-tool-execution"></a>

## 缺口二：并行执行工具

当前模型经常在一轮中返回多个 `tool_use` 块。你的循环逐一执行它们，做法正确却很慢——三个各耗时三十秒的命令总共需要九十秒。SDK 会并发运行彼此独立的工具调用，并通过子智能体将同一思路扩展到更大尺度：在全新的上下文窗口中执行委派的工作，只把最终报告返回父智能体。

<a id="gap-three-sandboxing"></a>

## 缺口三：沙箱

第二部分承认，那道权限关卡并不严密：前缀匹配会放行 shell 元字符，而 `input()` 只有在你守在旁边时才有用。SDK 提供了[作为运行框架的 Claude Code](claude-code-as-harness.md)中描述的完整权限系统——设置中的允许列表规则、权限模式、沙箱命令执行，以及以确定性方式阻断操作的 `PreToolUse` 钩子。策略由代码执行，不必寄希望于你恰好坐在键盘前。

<a id="gap-four-resume"></a>

## 缺口四：恢复

在任务进行到一半时终止你的智能体，一切就都没了；对话记录只存在于一个 Python 列表中。SDK 的会话会在多次交互之间持久保存状态，允许你以后恢复对话或从中创建分支。再配合从 `.claude/` 加载的记忆文件，智能体每次开始会话时就已经了解项目，无需重新探索。

<a id="the-decision-rule"></a>

## 决策规则

只要至少满足以下一个条件，就适合自己构建：你正在学习（这也是本手册存在的原因）；循环本身就是你的产品，你需要掌控每一行代码；或者任务范围足够小——两三个工具、短会话、有人在场——150 行代码确实足以覆盖。许多有用的内部工具，保持这个规模就能很好地工作。

一旦出现以下任一情况，就采用现成运行框架：智能体需要无人值守运行；它会读取不可信内容（网页、邮件、别人的代码）；会话长到压缩质量决定成败；或者你发现自己开始认真搭建权限系统。这些问题中的每一个，都意味着数月不起眼的工程工作，而 Anthropic 等团队已经做过，并针对你尚未遇到的失效模式进行了测试。重新实现并不等于严谨，只是增加成本。

坦诚地说，这 150 行代码从来都不是终点。它们让你再次阅读框架文档时，看到的是设计选择，而不是魔法——你知道没有包装的循环是什么样子，就能分清哪些外衣能保暖，哪些只是装饰。从[生态概览](harness-landscape.md)中选一个框架，接上真实任务，并继续阅读对话记录。
