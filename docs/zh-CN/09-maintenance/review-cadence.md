# 回顾节奏

检查保持结构健全，回顾让你持续参与其中。它也是唯一会产出你真正阅读的东西，而不只是静默执行的维护任务。

<a id="weekly-ten-minutes"></a>

## 每周，十分钟

智能体准备，你来阅读。

```
/review
```

返回的内容包括：新增了什么、哪些概念的链接增长最多、记录了哪些矛盾且仍未解决、还有哪些开放问题，以及接下来值得读或写的三件具体事情。

聚类最值得关注。上周链接流向哪里，你的注意力实际上就在哪里，而这通常与你以为自己关注的地方不同。

<a id="monthly-structurally"></a>

## 每月，从结构上回顾

每月一次，关注整个知识库，而不是只看这一周：

- 将四项[指标](../05-graphs/metrics.md)追加到一份笔记中，形成趋势记录
- 主题不断增加来源，却已有九十天未更新的概念页面
- `index.md` 中的 Gaps 清单，这是一份你无意中生成的阅读清单
- 选一篇最近写的页面，查看其局部图谱，抽查链接质量

<a id="quarterly-honestly"></a>

## 每季度，诚实地回顾

两个问题。

**我对哪些事情改变了看法？** 只有遵循[取代规则](../04-structuring/contradictions-and-supersession.md)才能回答；仅这一项就足以让整个系统值得投入。

**我保留了哪些永远不会用的东西？** 把它们归档。带着无用材料的知识库，会让每次查询都稍微变差，而且一直如此。

<a id="what-to-prune"></a>

## 清理什么

不再关心的主题来源：归档而非删除，它们留在 `raw/` 中几乎没有成本，而对应的 wiki 页面可以移除。

始终没有第二个来源的概念页面：通常意味着这个想法对你其实并不重要。

不要清理仍被链接依赖的页面。一篇被另外五页依赖的页面，无论读起来怎样，都是结构支点。

<a id="keep-the-review-short"></a>

## 保持回顾简短

把所有内容都列出来的回顾，只会被草草扫过，随后遭到忽略。推荐三件事，而不是十件。如果某一周没有值得报告的变化，用一行说明即可。
