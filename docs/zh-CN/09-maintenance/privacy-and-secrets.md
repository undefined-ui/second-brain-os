# 隐私

成熟的第二大脑，是关于一个人信息密度最高的文档之一。你读过什么、做过什么、担忧什么、问过什么，都被连接并建立了索引。

这正是它的价值，也是必须慎重决定放入什么、存在哪里的原因。

<a id="decide-at-capture-not-later"></a>

## 采集时决定，而非事后处理

导入后再脱敏行不通。等到你意识到某个内容不该存在时，它已经传播到概念页面、链接和综合页面中，删除它意味着要找出所有这些位置。

在文件进入 `raw/` 之前就做决定。参见[聊天记录导出](../03-ingestion/chat-exports.md)：聊天历史的信息比其他任何来源都多，又是批量导入，因此这里的问题最严重。

<a id="what-does-not-belong"></a>

## 哪些内容不该放进来

**任何类型的凭据。** 不是因为智能体会泄露，而是知识库会被同步、提交、备份，偶尔还会被分享。每多一份副本，密钥就多存在于一个地方。

**他人的私人信息。** 会议记录、私人消息，以及任何他人私下告诉你的内容。你的笔记不适合存放别人的秘密，而且他们没有同意被纳入知识库。

**你有合同义务保密的材料。** 把受保密协议约束的客户工作放入会同步到个人云账号的知识库，会造成真实的泄密风险。

<a id="separate-vaults-over-careful-filtering"></a>

## 分开知识库，胜过小心过滤

如果有些材料绝不能混在一起，就使用独立知识库，而不要依靠同一知识库中的标签或文件夹。

在单个知识库里划分私密区域，需要每次查询、每次导出和每次发布都遵守边界。两个知识库则不会相互混入内容，代价只是你需要选择打开哪一个。

<a id="local-models-for-sensitive-material"></a>

## 敏感材料使用本地模型

如果某类材料完全不应离开你的机器，就用本地模型处理那个知识库的导入。它的质量低于前沿模型，这是需要接受的取舍。

对医疗、法律或财务材料，这种取舍值得；对软件相关文章，通常不值得。

<a id="publishing"></a>

## 发布

必须明确选择加入。参见[发布与导出](../08-outputs/publishing-and-export.md)。

<a id="before-sharing-a-vault"></a>

## 分享知识库之前

搜索其中的密钥，检查 frontmatter 中的个人标识，阅读日志以确认导入了什么、来自哪里。一旦分享，内容就已经流出，而图谱会让读者很容易拼出一幅你原本无意展示的画像。
